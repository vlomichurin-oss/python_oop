# ЛР-6 — Generics и typing

## 1. Цель работы
* Освоить систему аннотаций типов в Python (`typing`).
* Научиться создавать **обобщённые (generic) классы** с помощью `TypeVar` и `Generic`.
* Понять концепцию **структурной типизации** через `typing.Protocol`.

## 2. Описание реализованных типов и контейнеров

### Generic-классы

**Generic class** - это класс, который может работать с разными типами данных, не привязываясь к конкретному типу. Параметр типа указывается при создании экземпляра, что обеспечивает типобезопасность и переиспользование кода.

**`TypedCollection[T]`** - типизированная коллекция для хранения элементов одного типа. Обеспечивает типобезопасность и поддерживает базовые операции (добавление, удаление, получение всех элементов), а также методы поиска `find()`, фильтрации `filter()` и преобразования `map()`.

### TypeVar

**TypeVar** - это специальный объект из модуля `typing`, который используется для объявления параметров типа в generic-классах и generic-функциях. Он позволяет создавать обобщённый код, который может работать с разными типами данных.

- **`T`** - свободный тип без ограничений
- **`R`** - тип результата для метода `map()`
- **`D`** - тип с ограничением `bound=Displayable` (требует метод `display()`)
- **`S`** - тип с ограничением `bound=Scorable` (требует метод `score()`)

### Протоколы

**Protocol** - это класс из модуля `typing`, реализующий концепцию структурной типизации (утиной типизации). Протокол определяет набор методов или атрибутов, которыми должен обладать объект, без требования явного наследования.

**`Displayable`** - требует метод `display() -> str`. Соответствуют классы `Warrior`, `Mage`, `Archer`, `Player` - все они имеют этот метод для строкового отображения объекта.

**`Scorable`** - требует метод `score() -> float`. Соответствуют классы `Warrior`, `Mage`, `Archer`, `Player` - все они имеют метод для вычисления числовой характеристики (силы/мощи).


## 3. Демонстрация

**Сценарий 1:** Создаётся коллекция `TypedCollection[Warrior]`, в неё добавляются три объекта класса `Warrior`. Демонстрируется получение всех элементов через `get_all()`, вывод количества элементов через `len()`, удаление элемента через `remove_at()` и повторный подсчёт оставшихся элементов. **Сценарий 2:** Демонстрируются три метода. `find()` ищет мага с уровнем больше 8 (элемент найден) и больше 15 (возвращается `None`). `filter()` отбирает магов с уровнем 7 и выше, возвращая список найденных объектов. `map()` показывает смену типа результата: преобразование в `list[str]` (имена магов), `list[int]` (уровни) и `list[float]` (сила магов).

**Сценарий 3:** Создаётся коллекция `TypedCollection[Displayable]`, в которую добавляются объекты `Warrior`, `Mage`, `Archer`, `Player` без явного наследования от протокола. Вызывается метод `display()` для каждого объекта. Затем создаётся коллекция `TypedCollection[Scorable]` с теми же объектами, вызывается метод `score()`. Демонстрируется работа `find()` и `map()` с протоколами. Это показывает, что классы соответствуют протоколам структурно (по наличию методов), а не номинативно (по наследованию).

## 4. Вывод

- **Аннотации типов** - позволяют явно указывать типы параметров и возвращаемых значений, делая код самодокументируемым и позволяя статическим анализаторам находить ошибки до выполнения программы.

- **Generic и TypeVar** - дают возможность создавать обобщённые классы и функции, работающие с разными типами данных. Параметр `TypeVar` с ограничением `bound` позволяет задавать требования к типам (например, наличие метода `display()`).

- **Protocol** - реализует структурную типизацию: объект соответствует протоколу, если у него есть нужные методы, без явного наследования. Это делает код более гибким и слабосвязанным.

- **Польза типизации** - типы служат документацией, упрощают чтение кода, помогают IDE (автодополнение, рефакторинг) и позволяют ловить ошибки на этапе разработки, а не во время выполнения.
