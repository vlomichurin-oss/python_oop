## 2. Описание интерфейсов

### 2.1 Printable (Интерфейс для вывода)

Интерфейс `Printable` предназначен для объектов, которые могут быть представлены в виде строки. Содержит один абстрактный метод `to_string()`, который возвращает строковое представление объекта. Классы, реализующие этот интерфейс, должны определить собственный формат вывода данных.

**Метод:**
- `to_string() -> str` — возвращает строковое представление объекта

---

### 2.2 Comparable (Интерфейс для сравнения)

Интерфейс `Comparable` предназначен для объектов, которые можно сравнивать между собой. Содержит абстрактный метод `compare_to()`, который сравнивает текущий объект с другим. Классы, реализующие этот интерфейс, определяют собственную логику сравнения (по уровню, важности, силе и т.д.).

**Метод:**
- `compare_to(other) -> int` — сравнивает текущий объект с другим
  - возвращает отрицательное число, если текущий объект меньше `other`
  - возвращает `0`, если объекты равны
  - возвращает положительное число, если текущий объект больше `other`

---

### 2.3 Identifiable (Интерфейс для идентификации)

Интерфейс `Identifiable` предназначен для объектов, имеющих уникальный идентификатор. Содержит абстрактный метод `get_id()`, который возвращает строковый идентификатор объекта. Классы, реализующие этот интерфейс, формируют ID по собственному правилу (с разными префиксами).

**Метод:**
- `get_id() -> str` — возвращает уникальный идентификатор объекта

## 3. Классы и их реализация в `models.py`

## Описание классов

### 3.1 Player (Игрок)

Класс `Player` реализует все три интерфейса: `Printable`, `Comparable`, `Identifiable`.

**Реализация интерфейсов:**
- `to_string()` — выводит информацию об игроке: никнейм, класс, уровень, здоровье, статус (жив/мёртв)
- `compare_to()` — сравнивает игроков по **уровню**
- `get_id()` — возвращает ID в формате `player_никнейм`

**Собственные методы:**
- `is_alive()` — проверяет, жив ли игрок
- `take_damage(damage)` — наносит урон
- `heal(amount)` — лечит игрока
- `level_up()` — повышает уровень

---

### 3.2 NPC (Неигровой персонаж)

Класс `NPC` также реализует все три интерфейса, но с **другой логикой**.

**Реализация интерфейсов:**
- `to_string()` — выводит информацию о NPC: имя, тип, важность (в виде звёздочек)
- `compare_to()` — сравнивает NPC по **важности** (от 1 до 10)
- `get_id()` — возвращает ID в формате `npc_имя`

**Отличие от Player:**
| Метод | Player | NPC |
|-------|--------|-----|
| `to_string()` | показывает уровень и HP | показывает важность ★ |
| `compare_to()` | сравнение по уровню | сравнение по важности |
| `get_id()` | префикс `player_` | префикс `npc_` |

---

### 3.3 PlayerCollection (Коллекция игроков)

Класс `PlayerCollection` управляет коллекцией объектов `Player`.

**Базовые методы:**
- `add(player)` — добавляет игрока
- `remove(player)` — удаляет игрока
- `get_all()` — возвращает всех игроков

**Методы для работы с интерфейсами:**
- `get_printable_items()` — фильтрация объектов с интерфейсом `Printable`
- `get_comparable_items()` — фильтрация объектов с интерфейсом `Comparable`
- `get_identifiable_items()` — фильтрация объектов с интерфейсом `Identifiable`

**Сортировка:**
- `sort_by_comparable()` — сортировка через интерфейс `Comparable`

**Поиск и фильтрация:**
- `find_by_nickname(nickname)` — поиск по никнейму
- `get_alive()` — возвращает только живых игроков
- `get_by_class(player_class)` — фильтрация по классу
