# ЛР-7 — Консольное приложение

## 1. Цель работы
Создать консольное приложение для управления игроками, объединив все знания из предыдущих лабораторных работ.

### Что сделано:
- Консольное меню с 8 пунктами
- Добавление, удаление, поиск игроков
- Фильтрация и сортировка данных
- Сохранение и загрузка данных в файл

## 2. Структура проекта
- `main.py` - Запуск приложения, загрузка данных при старте, сохранение при выходе
- `cli.py` - Только ввод/вывод, отображение меню, получение данных от пользователя, форматированный вывод таблиц
- `app.py` - Бизнес-логика: добавление, удаление, поиск, фильтрация, сортировка
- `base.py` - Абстрактный класс Player с валидацией и базовыми методами
- `models.py` - Конкретные классы: Warrior, Mage, Archer с уникальными способностями
- `collection.py` - Класс-контейнер для хранения игроков с методами поиска и фильтрации
- `storage.py` - Сериализация/десериализация объектов в JSON
- `exceptions.py` - Ошибки

## 3. Описание меню

### Что делает каждый пункт

**Пункт 1** - Создать нового игрока. Нужно ввести никнейм, класс (warrior/mage/archer), уровень, здоровье и опыт.

**Пункт 2** - Показать всех игроков в виде таблицы с колонками: номер, никнейм, класс, уровень, здоровье, опыт, статус.

**Пункт 3** - Найти игрока. Можно искать по никнейму или по классу.

**Пункт 4** - Удалить игрока. Программа сначала спрашивает подтверждение "Удалить? (y/n):" и только потом удаляет.

**Пункт 5** - Фильтрация игроков. Можно показать только живых, только с уровнем выше заданного, только с здоровьем выше заданного или только игроков определенного класса.

**Пункт 6** - Сортировка игроков. Можно отсортировать по никнейму (А-Я или Я-А), по уровню (от меньшего к большему или наоборот) или по здоровью.

**Пункт 7** - Показать статистику. Выводится общее количество игроков, средний уровень, среднее здоровье, количество живых игроков и сколько игроков каждого класса.

**Пункт 0** - Выход из программы. Все данные автоматически сохраняются в файл.

### Сохранение и загрузка:

- **При запуске:** программа ищет файл `players.json` и загружает игроков
- **При выходе:** все игроки сохраняются в `players.json`
- Если файла нет — создаётся новый

## 5. Вывод

### Разбиение на модули и слои

Программа разделена на несколько файлов, каждый отвечает за свою часть:
- `cli.py` - меню и ввод/вывод
- `app.py` - основная логика работы с игроками
- `storage.py` - сохранение и загрузка файлов
- `base.py` и `models.py` - классы игроков
- `collection.py` - хранение и поиск игроков
- `exceptions.py` - собственные ошибки

### CLI-интерфейс

Создано консольное меню с 8 пунктами. Программа работает в цикле: после каждого действия меню показывается снова. Для опасных действий (удаление игрока) запрашивается подтверждение "y/n". Все данные выводятся в виде таблицы.

### Обработка исключений

Используются стандартные ошибки Python (`ValueError`, `TypeError`) и собственные:
- `PlayerNotFoundError` - игрок не найден
- `DuplicatePlayerError` - игрок с таким ником уже есть

Все ошибки перехватываются и выводят понятное пользователю сообщение.

### Работа с файлами 

При запуске программа загружает игроков из файла `players.json`. При выходе - сохраняет. Если файла нет, он создаётся автоматически.

### Типизация

Все функции и методы в программе снабжены аннотациями типов:

- Указываются типы параметров: `nickname: str`, `damage: int`, `players: List[Player]`
- Указываются типы возвращаемых значений: `-> None`, `-> bool`, `-> List[Player]`
- Используются типы из модуля `typing`: `List`, `Optional`, `Callable`, `Any`
- Это помогает находить ошибки на этапе написания кода и делает код самодокументируемым
